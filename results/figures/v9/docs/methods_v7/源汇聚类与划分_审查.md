# 源与汇的聚类与划分——审查与改进

**一句话结论：源侧聚类是干净的，汇侧聚类只有一处标签错误，真正坏掉的是把两者连起来的候选管网——
它被强制成平面图，代价是 7 个厂址（20.4 GW）永远够不到任何封存汇，471 GW 被绕远路，
而在控制真实距离之后，在离汇 150 km 以内的厂址里，被绕远的 CCS 采纳率是 9%，没被绕远的是 50%。
更关键的是：修这个问题所需的机制（`top_k_storage_pairs`、`direct_fallback_capex_multiplier`）
在代码里已经声明好了，只是从来没有被实现。**

**修好之后重解（第 8 节）：主结论稳住并变强（水约束的成本效应 +1.340% → +1.933%，
干冷改造 +227.6 → +223.9 GW），但 2060 年的捕集量从 803 涨到 1 266 Mt/yr——
附录里所有 CCS/BECCS 绝对量的图都必须重画。管网伪影的代价是整个系统目标的 7.5%。**

**没有问题的地方（同样重要，因为这些正是审稿人会先怀疑的）：**

- **源侧聚类没有破坏流域约束。** 350 个枢纽里只有 22 个跨一级流域界，涉及 32.1 GW（2.3%）；
  四个受限流域的容量纯度都 ≥0.97。而且模型根本不用硬流域归属——每个厂址在 200 km 内平均
  连到 4.5 个水文节点，取水是在节点上竞争的。
- **汇聚类不影响全国注入能力上限。** 有效注入率 = `pixel_count/100 × 2 Mt/yr`，
  在合并下可加，35 个枢纽里只有 1 个碰到 200 Mt/yr 的帽子，损失 1 Mt/yr。全国 1 282 Mt/yr
  对聚类阈值在 0–300 km 之间完全不变。
- **1.5× 海上输送系数用对了。** 103 个原始地质体里没有任何一个合并把陆上和海上混在一起。
- **水量物理没有被聚类平均掉。** `capacity_mw_once_through / recirculating / air` 三列是精确的，
  强度是按容量加权算的；被众数污染的只有*标签*，不是物理量。

## 1. 源侧：3 623 台机组 → 350 个枢纽

### 1.1 它实际做了什么

`plants_unit.csv` 里 `plant_site` 是**电厂真名**，共 1 259 个真实电厂。
`_cluster_plants_to_hubs`（`builders/plants.py:348`）在建表时把机组坐标做层次聚类：

```python
DEFAULT_N_HUBS = 350                       # 注释只有一句"默认空间枢纽数"
clustering = AgglomerativeClustering(
    n_clusters=n_hubs, metric="precomputed", linkage="average")
```

标签 `H350_###` **只存在于内存里**——它不写回 `plants_unit.csv`，
所以机组→枢纽的对应关系在磁盘上没有留痕，要复现只能重跑聚类。这本身是个可复现性缺口。

### 1.2 几何质量：比预想的好

| 分位 | 机组数 | GW | 枢纽直径 | 最远机组到形心 |
|---|---|---|---|---|
| 中位 | 6 | 2.64 | **32.2 km** | 21.4 km |
| p90 | 23 | 8.83 | 72.9 km | 47.3 km |
| p99 | 55 | 24.44 | 96.8 km | 60.4 km |
| 最大 | 70 | **27.92** | **105.8 km** | 68.2 km |

容量加权的"机组到本枢纽形心"平均距离是 **16.3 km**。没有任何枢纽直径超过 200 km。
对一个国家尺度的 MILP 来说这是可以接受的空间粒度。

### 1.3 真正的代价：属性被众数抹平

`build_plant_dataframe` 用 `most_common_string`（`plants.py:99`）取众数——**按台数，不按容量**。

| 属性 | 跨类枢纽数 | 被贴错标签的容量 | 台数众数 ≠ 容量众数 |
|---|---|---|---|
| 省份 | 31 / 350 | **87.9 GW（6.2%）** | 6 个枢纽，54.0 GW |
| 冷却方式 | 145 / 350 | **262.7 GW（18.6%）** | 36 个枢纽，191.9 GW |
| 一级流域 | 22 / 350 | 32.1 GW（2.3%） | — |

最刺眼的一例：**H350_035，70 台机组 27.9 GW，坐落在上海坐标上，
按台数众数被整体记到了江苏**——按容量众数本该是上海。附录的分省图（ED8/ED9）继承了这个归属。

**冷却方式那 262.7 GW 需要拆开看，否则会夸大聚类的罪。**
在 k=1 259（完全不聚类、就是真实电厂）时，标签错配仍有 46.9 GW——那是真实的多机组电厂
本来就同时有直流和空冷机组。所以：

```
262.7 GW 总错配  =  46.9 GW 真实（电厂内部就是混的）  +  145.8 GW 由聚类制造
```

这一条对本文特别重要，因为论文的机制正是"哪些厂址做湿转干改造"。
之前测出来"改造者的判别变量是湿塔份额（中位 1.00 对 0.48）"——
那个判别量有一半以上是聚类混合度制造出来的，而不是纯粹的电厂属性。
**这不否定结论（水量物理是精确的），但它意味着"湿塔份额"应该被描述成
枢纽层面的混合参数，而不是被当成一个电厂特征来解释。**

### 1.4 这个标签问题会不会推翻附录图 ED3？——不会，而且换了标签之后更强

ED3 按 `dominant_cooling_technology` 分组，正是被众数污染的那一列。直接换成容量众数重算：

| 分组规则 | | GW | 厂址数 | 取水 | 定额 | 耗水 |
|---|---|---|---|---|---|---|
| **台数众数（现图）** | 直流 | 349.9 | 71 | **38.95** | **0.57** | 0.36 |
| | 湿塔 | 863.8 | 234 | 9.28 | 2.03 | 1.32 |
| | 空冷 | 202.5 | 45 | 1.83 | 0.76 | 0.36 |
| **容量众数（重标）** | 直流 | **486.2** | 94 | **34.34** | **0.72** | 0.44 |
| | 湿塔 | 680.5 | 201 | 7.00 | 2.27 | 1.49 |
| | 空冷 | 249.6 | 55 | 2.23 | 0.85 | 0.43 |

**秩反转在两种规则下都成立，而且换成容量众数后更强**：
直流/湿塔的取水比从 4.20× 升到 4.91×，定额比从 0.28 升到 0.32（仍然 <1）。
"全国取水口径下最渴的技术，在定额口径下最不渴"这句话不是标签伪影。

但**图上的数字会变**：直流主导厂址从 71 个 349.9 GW 变成 94 个 486.2 GW，
取水强度从 38.95 变成 34.34。若采纳第 6 节建议 4（众数改按容量加权），
ED3 的两处标注需要同步更新。

### 1.5 能不能改进？做了两组扫描

**（a）换 linkage（k 固定 350）**

| 方案 | 最大直径 | 容量加权半径 | 跨省 GW | 跨冷却 GW | 跨流域 GW |

| **现状 average / haversine** | 105.8 | 16.3 | 81.4 | 192.7 | 32.1 |
| complete / haversine | **79.4** | 16.2 | **62.2** | 198.2 | 36.6 |

| ward，按省+冷却分层 | **646.2** | 24.4 | 0 | **0** | 42.4 |

结论很干脆：**分层是个陷阱。** 把省份或冷却方式做成硬约束确实能把对应的错配清零，
但代价是新疆、内蒙这类大省被迫产生直径 372–646 km 的枢纽，
空间聚合误差反而变大，流域错配还从 32.1 涨到 42.4 GW。**不要做分层。**

唯一免费的改进是 `average` → `complete`：最大直径降 25%，跨省降 24%，容量加权半径不变。

**（b）换 k（这才是真正的杠杆）**

不是一个来历不明的 350，写进方法学时可以直接说清楚。

## 2. 汇侧：103 个地质体 → 35 个枢纽

### 2.1 它做了什么

栅格 → 2 像元膨胀桥接 → 连通分量 → **103 个地质体**（33 DSA + 70 EOR，1 902 Gt，67 542 个 5 km 像元）
→ `_cluster_storage_nodes` 用 **complete linkage、200 km 距离阈值**联合合并 DSA 与 EOR
→ 再迭代合并直到任意两个形心间距 ≥200 km → **35 个枢纽**。

### 2.2 做对的两件事

**注入能力的推导是对的，而且对聚类免疫。** 栅格逐像元注入率求和是 555 Gt/yr——没有工程含义，
代码只把它当**地质上限**，真正起作用的是候选场址密度：

```
hub injectivity = (hub 像元数 / 100) × 2 Mt/yr，上限 200 Mt/yr
```

即 50×50 km 一个项目、每个 2 Mt/yr。全国 **1 282 Mt/yr**，落在 ACCA21/CAEP 2060 年
1 000–1 800 Mt/yr 区间内。因为像元数在合并下可加，这个总量对阈值在 0–300 km 之间完全不变
（35 个枢纽里只有 1 个碰到 200 Mt/yr 的帽子，全国损失 1 Mt/yr）。

**海陆没有混。** 逐个检查 103 个地质体的合并分组，**没有任何一组同时含陆上和海上地质体**，
所以 `offshore_transport_multiplier = 1.5` 是干净地作用在 8 个海上枢纽（907 Gt，475 Mt/yr，
占全国注入能力 37%）上的。

### 2.3 做错的一件事：EOR 的收益抵扣被合并吃掉了

`_merge_group` 把合并后的 `storage_type` 定为 DSA 与 EOR 里**储量较大的那个**：

```python
stype = "dsa" if dsa_mt >= eor_mt else "eor"
```

而 `data_prep.py:206-209` 按这个标签定价：EOR 的封存成本 = 32 − 12 = 20 CNY/t，DSA = 32 CNY/t。

70 个 EOR 地质体被折进 35 个枢纽后只剩 6 个还叫 `eor`：
**7 232 Mt 的 EOR 储量被贴上 dsa 标签，丢掉了 12 CNY/t 的抵扣**（反向只有 74 Mt）。
方向上这又是一个**系统性压低 CCS 吸引力**的偏差，和第 3 节的管网问题同向叠加。

**修法很简单，也不用改求解器**：把 `storage_cost_cny_per_t` 改成按储量加权的混合价，
而不是按标签取一个：

```python
w_eor = eor_mt / (dsa_mt + eor_mt)
storage_cost = assumptions.storage_cost_cny_per_t - w_eor * assumptions.eor_credit_cny_per_t
```

### 2.4 200 km 阈值本身的代价

| 阈值 | 枢纽数 | 容量加权 厂→最近汇 直线距离 | 中位 | p90 | 全国注入 |
|---|---|---|---|---|---|
| 0（不合并） | 103 | **200 km** | 186 | 413 | 1 350 |
| 50 | 74 | 204 | 191 | 418 | 1 350 |
| 100 | 49 | 212 | 200 | 438 | 1 350 |
| **200（现状）** | **35** | **234 km** | 216 | 455 | 1 350 |
| 300 | 26 | 249 | 238 | 457 | 1 350 |
| 400 | 19 | 293 | 275 | 582 | 1 319 |

合并到 200 km 的代价是 **+34 km 的容量加权输送距离（+17%）**，
按模型自己的 0.179 CNY/(t·km) 折合 **+6.1 CNY/t**。相对 CCS 改造资本的 ~118 CNY/t，
这是个可以接受的量级，不是主要问题。100 km 阈值（49 个枢纽，+12 km）是一个更保守的选择。

**另外：`storage_hubs.csv` 的 `province` 列 35 行全是 NaN**——写了列却从没填。
优化里没人读它，但附录图若想按省汇总封存能力会取到空值。

## 3. 源—汇之间：真正的问题在这里

### 3.1 候选管网是怎么建的

节点 612 个：350 电厂 + 35 封存枢纽 + 167 管道交叉点 + 60 管道端点。
边 923 条：596 三角剖分候选 + 240 枢纽接入支线 + 62 既有主干（油/气）+ 25 汇接入支线。
**其中电厂—封存枢纽的直接边只有 96 条。**

生成规则：终端点做 Delaunay 三角剖分 → 丢掉长度 >500 km 的边 →
丢掉"既有路径已经不超过直连 1.2 倍"的边 → **最后 `_remove_crossing_edges` 强制平面化**。

### 3.2 平面化把端点切断了

```python
# builders/network.py:361
def _remove_crossing_edges(nodes, edges):
    """Remove lower-priority edges that cross higher-priority ones.
    Guarantees a planar candidate network."""
```

按优先级（既有主干 > 支线 > 三角剖分）贪心保留，**同级按文件行序**决定谁被丢。
后果：

| 后果 | 规模 |
|---|---|
| 完全没有任何边的电厂节点 | 4 个 |
| 有边但所在连通分量里没有封存汇 | 3 个 |
| **合计永远无法做 CCS 的容量** | **7 个厂址，20.38 GW（占机组 1.44%）** |
| 被绕行 >1.5× 直线距离的容量 | **471.2 GW（33.3%）** |
| 被绕行 >2× | 372.0 GW（26.3%） |
| 被绕行 >3× | 228.7 GW（16.1%） |

最极端的两例：

- **P0044（黑龙江，2.955 GW）距离封存枢纽 S004 只有 24.5 km，却一条边都没有。**
- **P0077（7.82 GW）距离最近的汇 12.0 km，网络里的最短路径是 617.7 km——绕了 51 倍。**

### 3.3 这个偏差有多大

以文献常用的"直线 × 1.3 地形系数"为参照（IEAGHG/ZEP 与 SimCCS 系列在没有成本面时用 1.2–1.4），
按模型自己的平准化输送成本 0.179 CNY/(t·km)：

```
容量加权多绕     +99 km   =  +17.7 CNY/t CO2
承担 >50 CNY/t 的容量      247.2 GW（17.5%）
承担 >100 CNY/t 的容量     140.3 GW（ 9.9%）
参照：CCS 改造资本 4 000 CNY/kW，4 500 h/yr、0.85 tCO2/MWh、90% 捕集、
      20 年 8% 年金  ->  约 118 CNY/t
```

也就是说，**对那 140 GW 而言，纯粹由候选网络几何造成的输送成本几乎让 CCS 的交付成本翻倍。**

### 3.4 它确实咬了：解出来的结果证实了

在 `WA_cwatm_126_dry_wd085`（2060 年）按绕行成本分四分位：

| 分位 | 厂址数 | GW | 绕行成本中位 | 采纳 CCS 的厂址比例 | 捕集量 |
|---|---|---|---|---|---|
| Q1 低 | 88 | 412.8 | −13.6 CNY/t | 34% | 240.6 Mt |
| Q2 | 87 | 378.3 | −6.3 | **44%** | **304.2 Mt** |
| Q3 | 87 | 261.7 | +6.8 | 32% | 212.5 Mt |
| **Q4 高** | 88 | 363.4 | **+69.0** | **6%** | **44.7 Mt** |

那 7 个够不到汇的厂址，2060 年捕集量精确为 0.00 Mt——如预期。

**但四分位可能只是在说"Q4 本来就远"。所以控制真实距离再看一次：**

| 到最近汇的直线距离 | 未被绕行 | 被绕行（网络路径 >1.5× 直线） |
|---|---|---|
| <150 km | 58 厂址 209.9 GW，**CCS 采纳 50%**，214.7 Mt | 32 厂址 143.6 GW，**CCS 采纳 9%**，26.7 Mt |
| 150–300 km | 99 厂址 491.7 GW，35%，255.5 Mt | 50 厂址 201.1 GW，18%，66.7 Mt |
| 300–500 km | 50 厂址 171.4 GW，40%，163.7 Mt | 34 厂址 118.9 GW，**9%**，35.7 Mt |
| >500 km | 15 厂址 51.8 GW，13%，39.2 Mt | 5 厂址 7.7 GW，0%，0.0 Mt |

**在离汇最近的那一档里，被网络绕远的厂址采纳 CCS 的比例是 9%，没被绕远的是 50%；
在 300–500 km 一档是 9% 对 40%。四个距离档里方向完全一致。**
标准化线性概率模型给出：真实距离系数 −0.064，绕行长度系数 **−0.126**——
**几何伪影的影响是真实距离的两倍。**

（诚实的限定：这是横截面对比，被绕行的厂址可能在别的方面也不同。
决定性的检验是重解——见第 5 节。）

### 3.5 最讽刺的一点：修复机制早就设计好了，只是没写

```python
# optimization/scenario.py
direct_fallback_capex_multiplier: float = 2.8    # data_prep.py:610 读它
top_k_storage_pairs: int = 5                     # 全仓库零引用
```

`data_prep._edge_capex_multiplier` 专门为一个叫 `runtime_direct_fallback` 的边类定价，
**而整个仓库里没有任何地方产生这个边类**。
两个参数合在一起，意图非常明确：*每个电厂应当有到最近 5 个封存枢纽的直连候选弧，
按 2.8 倍资本溢价计价*。这个机制被设计出来、被定价、然后从未实现。
上面那 7 个孤立厂址和 471 GW 的绕行，是一个半成品功能的后果，不是一个建模选择。

### 3.6 已实现的修复及其几何效果

新增 `scripts/build_direct_source_sink_edges.py`：为每个电厂加到最近 5 个汇的直连弧，
长度 = 直线 × 1.3，边类用现成的 `runtime_direct_fallback`（于是 2.8× 溢价自动生效）。
**只加不减**——优化器永远可以复现旧解，凡是它改变的都是它自己选择改变的。

```
新增 1 654 条弧，边数 923 -> 2 577

                              修复前     修复后
够不到汇的电厂                   7          0
绕行 >1.5× 的容量           471.2 GW    0.0 GW
绕行 >2.0× 的容量           372.0 GW    0.0 GW
绕行 >3.0× 的容量           228.7 GW    0.0 GW
绕行比中位                    1.17       1.14
绕行比 p90                    3.36       1.30
绕行比最大                   51.41       1.30
容量加权节省                  135 km  =  24.2 CNY/t CO2
```

中位数只从 1.17 动到 1.14——**说明这个修复精确地打在尾部，对绝大多数厂址什么都没改**，
这正是一个好修复该有的样子。

## 4. 顺带：水侧的"源—汇匹配"也是一个划分选择

`WATER_MATCH_BUFFER_KM = 200`（`constants.py:49`）。每个电厂连到 200 km 内的所有水文节点，
交付成本 `4.0 + 0.05 × d` CNY/m³。

| 指标 | 值 |
|---|---|
| 连接数 | 1 569（每厂平均 4.5 个节点） |
| 最近节点距离 | 中位 62.5 km，p90 103.9，最大 137.6 |
| 连接距离 | 中位 138.3 km，最大 199.9 |
| **能取到 >1 个一级流域的容量** | **846.9 GW（59.8%）** |
| 受限流域里"最近节点所在流域"占其可达节点的比例 | C 0.686、D 0.668、E 0.688 |
| 最近节点流域占比 <50% 的厂址 | 44 个，205.4 GW |

**这不是 bug——距离是计价的**（138 km 的输水成本 6.9 CNY/m³，是取水成本 4.0 的 1.7 倍），
而且用多节点竞争代替硬流域归属，恰恰化解了源侧聚类可能带来的流域错配。
但它是一个需要在方法学里明写的假设：**在这个模型里，一个海河流域的电厂可以在付输水费之后
从 190 km 外的黄河节点取水，没有任何调水工程约束。**
对北方那三个受限流域，可达节点里有三分之一在流域之外——
水约束的影子价格因此被一个未建模的"跨流域调水"部分释放了。

建议：在敏感性里加一组 `WATER_MATCH_BUFFER_KM = 50/100`，
或者对跨一级流域的取水连接加一个额外的调水惩罚。

## 5. 与当前文献的对照

| 环节 | 本模型 | 当前文献主流做法 |
|---|---|---|
| **源的粒度** | 3 623 台机组聚成 **350 个枢纽** | 机组或电厂级，**不做空间聚类**。全国尺度的中国 CCS 集群研究直接用 **946 座燃煤电厂**；安徽省级研究用 27 座电厂 |
| **汇的定义** | 栅格连通分量 → 103 个地质体 → 200 km 合并成 **35 个枢纽** | 按**地质单元/盆地**定义。全国研究用 **17 个主要盆地**，区分陆上/海上、EOR/DSA |
| **候选管网** | Delaunay + 既有油气走廊 + **强制平面化** | **SimCCS 2.0/3.0：Delaunay 三角剖分 + 成本面上的 Dijkstra 最小成本路径**。华北 CCUS 研究用 ArcGIS 成本路径（坡度、土地利用、道路、人口）+ 节省里程法 |
| **连通性保证** | 无——平面化会切断端点 | **SimCCS 明确保证每个源和汇至少有一条可行走廊，即使成本面被加权到强烈抑制穿越** |
| **管长** | 直线大圆距离 | 成本面最小路径；无成本面时用 1.2–1.4 地形系数 |

**最重要的一条对照是连通性。** SimCCS 的文档把"所有源和汇都必须至少被一条可行走廊连接"
写成了不变式，即使成本面被调成强烈抑制穿越也要保证。本模型做的恰好相反：
它把"穿越"当成硬禁止，然后接受端点被切断的后果。**平面性不是 CO₂ 管道的物理属性**——
现实中管道在不同埋深和路权上互相穿越。这个约束是为了几何整洁而加的，代价是 471 GW 的绕行。

如果确实想抑制穿越（比如为了避免走廊重复建设），文献给出的做法是**把它写进成本面而不是写成硬约束**——
穿越就加价，让优化器自己决定值不值。

## 7. 对论文结论的影响

**主结论走的是冷却方式这条链路，不经过管网。** +227.6 GW 的干冷改造是水约束下的适应，
它的成本项是空冷资本和发电效率惩罚，与 CO₂ 输送几何无关。所以第 1、2 条问题
**不直接推翻主结论**。

但它们**改变主结论的解释**，而且是同一个方向：

- 管网伪影压低 CCS（471 GW 绕行，控制真实距离后采纳率 9% vs 50%）
- EOR 标签错误压低 CCS（7 232 Mt 丢失 12 CNY/t 抵扣）

两者叠加，意味着模型里"改造 vs 捕集"的相对吸引力被系统性地推向了改造一侧。
论文的故事是"水约束把煤电推向干冷改造，代价由生物质承担"——
如果 CCS 的成本被人为抬高了，那么这个故事的**幅度**是被夸大的。

**这正是第 5 节那个重解要回答的问题**，它已经在跑：
在修好的候选网络上重解控制组与处理组，看
`(处理 − 控制)/控制` 是否仍然越过 0.3277% 的求解退化下限。
只加边不减边，所以两个解都不会比原来差，差异是不是稳健就一目了然。

## 8. 重解结果：主结论稳住了，但附录里 CCS 的水平全都偏低

两组解，输入只差 1 654 条直连弧（只加不减），各自 8 线程、MIPGap 1%：

### 8.1 主结论：不但稳住，而且更强

| | 效应 `(处理−控制)/控制` | 认证区间 | gap（控制/处理） | 越过 0.3277% 下限 |
|---|---|---|---|---|
| 现网（923 条边） | **+1.340 %** | [+0.639, +2.188] | 0.83 / 0.69 % | 4.09× |
| 修复后（2 577 条边） | **+1.933 %** | [+0.953, +2.944] | 0.98 / 0.96 % | **5.90×** |

**水约束的代价在修好的管网上不但没有消失，反而从 +1.340% 涨到 +1.933%。**
原因是自洽的：管网修好之后 CCS 变得便宜且大规模上马，而 CCS 把耗水强度抬到 1.82×——
于是"水不够"这件事在一个 CCS 真正可行的世界里更贵。**现网上报的效应是被低估的。**

**干冷改造的响应几乎不动**：2030 年 **+227.6 GW → +223.9 GW（−1.6%）**。
论文的中心数字对这个几何伪影是稳健的。

### 8.2 但绝对水平错得很厉害

| 2060 年 | 控制组现网 | 控制组修复后 | 处理组现网 | 处理组修复后 |
|---|---|---|---|---|
| CO₂ 捕集（Mt/yr） | 803.2 | **1 266.1（+58%）** | 802.0 | **1 277.0（+59%）** |
| CCS 改造（GW） | 18.1 | 46.6 | 19.4 | 51.6 |
| BECCS（GW） | 192.3 | 288.1 | 191.5 | 287.1 |
| 生物质掺烧（GW） | 431.6 | 342.1 | 432.6 | 330.1 |
| 采纳 CCS 的厂址数 | 101 | **132** | 101 | **141** |
| 干冷改造 2060（GW） | 13.9 | 32.3 | 45.5 | 85.0 |

**所有涉及 CCS/BECCS 绝对量的附录图都需要重画。** 捕集量偏低 58%，
采纳 CCS 的厂址数从 101 涨到 132–141——ED2、ED4、ED6 以及正文的管网图都会变。

### 8.3 目标函数下降 7.5% 是真实替代，不是罚金伪影

控制组目标从 13.955 降到 12.906（**−7.52%**），处理组 −6.98%。按成本项归因（1e12 CNY）：

| 项 | 变化 |
|---|---|
| **carbon_cost** | **−1.897** |
| transport_opex | +0.313 |
| ccs_retrofit_capex | +0.182 |
| pipe_capex | +0.178 |
| biomass_cost | +0.173 |
| energy_penalty_cost | +0.115 |
| ccs_om_cost | +0.102 |
| storage_cost | +0.087 |
| **合计** | **−1.050** |

**`slack_penalty` 在两组里都是 0.000/0.007**——所以这不是"现网被逼到违约罚金"造成的假象，
而是一次干净的替代：CO₂ 输送一便宜，系统就用多花 1.0e12 的 CCS 链条
换掉 1.9e12 的碳价支出。**管网几何伪影的代价是整个系统目标的 7.5%。**

### 8.4 一个尚未确定的问题：生物质那条"付账"链路

处理组减控制组的生物质掺烧，从现网的 **+0.9 GW** 变成修复后的 **−12.0 GW**；
同时 CCS 从 +1.3 变成 +5.0 GW，退役从 −1.5 变成 +7.9 GW。

**这个符号翻转还不能当结论。** 容量层面的求解退化下限只在正文图 4 的
走廊份额上标定过，生物质容量上没有对应的 null，而 12 GW 只占该项的 3.5%。
要确定"水的适应由生物质买单"这条链路在修好的管网上是否还成立，
需要在修复网络上跑 seed 复制（至少 3 个）来标定容量层面的噪声。**这是下一轮该做的事。**

### 8.5 结论

| 命题 | 状态 |
|---|---|
| 水约束的成本效应为正且显著 | **稳健**（+1.340 → +1.933%，区间严格为正，越过下限 5.90×） |
| 水约束驱动 +227.6 GW 干冷改造 | **稳健**（→ +223.9 GW，−1.6%） |
| 附录图里的 CCS/BECCS/捕集绝对量 | **偏低，必须重画**（捕集 −58%） |
| "水的适应由生物质买单" | 见第 9 节——第二轮把它判成噪声 |

## 9. 第二轮重解：汇与管网全部重建

第 8 节只加了直连弧。这一轮把**汇也重建**（103 个地质封存体、DSA/EOR 分列、不做距离合并）
并把**迂回系数 1.136** 应用到所有直线候选边上。输入相对现网差三件事，
相对第一轮只差汇的划分与迂回系数。

### 9.1 主结论：三代之间几乎不动

| | 效应 `(处理−控制)/控制` | 认证区间 | gap（控/处） | 越过下限 |
|---|---|---|---|---|
| 现网（35 汇 / 923 边） | +1.340 % | [+0.639, +2.188] | 0.83 / 0.69 % | 4.09× |
| 第一轮（35 汇 / 2 577 边） | +1.933 % | [+0.953, +2.944] | 0.98 / 0.96 % | 5.90× |
| **第二轮（103 汇 / 2 677 边）** | **+1.931 %** | [+0.915, +2.949] | 0.99 / 1.00 % | **5.89×** |

**第一轮和第二轮相差 0.002 个百分点。** 也就是说：
**7.5% 的目标下降、58% 的捕集增量，几乎全部来自管网连通性修复，
汇的重新划分在系统层面是小量。** 这是一个有用的分解——
汇侧那两处改动（103 个地质体、找回 7 232 Mt EOR 的抵扣）的价值在于**方法学站得住**，
不在于改变数字；真正咬人的是平面化把 471 GW 送去绕远路。

干冷改造响应：**+227.6 → +223.9 → +217.2 GW**，三代之间漂了 4.6%，
仍然比其他任何响应大两个数量级。

### 9.2 成本归因：与第一轮同构，仍然是干净替代

控制组目标 13.955 → 12.902（**−7.55%**），按成本项（1e12 CNY）：

| 项 | 变化 | | 项 | 变化 |
|---|---|---|---|---|
| **carbon_cost** | **−1.890** | | transport_opex | +0.314 |
| baseline_net_cost | −0.094 | | ccs_retrofit_capex | +0.175 |
| incremental_om | −0.060 | | pipe_capex | +0.161 |
| coal_savings_credit | −0.043 | | energy_penalty_cost | +0.113 |
| blend_upgrade_capex | −0.017 | | biomass_cost | +0.102 |
| | | | ccs_om_cost | +0.098 |
| | | | storage_cost | +0.085 |

`slack_penalty` **两组都是 0.0000**——不是被逼到违约罚金，是 CO₂ 输送变便宜之后
用 1.0e12 的 CCS 链条换掉 1.9e12 的碳价支出。

### 9.3 EOR 现在真的被用上了

| 2060 年注入量 | 现网 | 重建后 |
|---|---|---|
| DSA | 803.2 Mt/yr | 1 259.3 Mt/yr |
| **EOR** | **0.0** | **12.5 Mt/yr** |
| 实际注入的汇数 | 27 | **69** |

现网里 EOR 注入量精确为零——因为 70 个 EOR 地质体被合并后只剩 6 个还叫 `eor`，
其余的按 DSA 计价，没有 12 CNY/t 的抵扣就竞争不过。修好之后 EOR 拿到 12.5 Mt/yr。
量不大（EOR 全国储量只有 8.4 Gt），但**从"结构性为零"变成"按经济性参与"**。

### 9.4 生物质那条链路：判定为噪声，不是发现

第 8.4 节把处理组减控制组的生物质符号翻转列为"未定"。第二轮给了答案：

| 处理 − 控制 | 现网 | 第一轮 | 第二轮 |
|---|---|---|---|
| 2060 捕集（Mt/yr） | −1.2 | **+10.9** | **−10.7** |
| CCS 改造（GW） | +1.3 | +5.0 | +2.2 |
| BECCS（GW） | −0.8 | −1.0 | −5.1 |
| **生物质掺烧（GW）** | **+0.9** | **−12.0** | **+6.2** |
| 退役（GW） | −1.5 | +7.9 | −3.3 |
| 采纳 CCS 厂址数 | 0 | +9 | −5 |
| **2030 干冷改造（GW）** | **+227.6** | **+223.9** | **+217.2** |

**第一轮和第二轮的输入差别小到让目标效应只动 0.002 pp，
却让生物质的配对差摆了 18 GW 并跨过零。** 这就是容量层面求解退化的特征：
目标函数被识别得很好，容量的分配则没有。**这些小量不能用来讲机制。**

唯一在三代之间稳定的容量响应是干冷改造，它比其他项大两个数量级——
论文的机制链路正好走的是这一条，这是运气也是结构。

**对论文的影响**：不能再说"水的适应由生物质买单"。
可以说的是"水的适应主要以干冷改造实现"，以及成本效应为正且被认证。
生物质那条叙事若要保留，需要在同一套输入上做 seed 复制来标定容量噪声，
现在它连符号都不稳。

### 9.5 三代对照的最终结论

| 命题 | 状态 |

| 水约束的成本效应为正且显著 | **稳健**：+1.340 / +1.933 / +1.931 %，三代区间都严格为正，越过下限 4.1–5.9× |
| 水约束驱动约 +220 GW 干冷改造 | **稳健**：+227.6 / +223.9 / +217.2 GW |
| 管网几何伪影值 7.5% 的系统目标 | **已量化**，且归因干净（碳价 −1.9e12 换 CCS 链条 +1.0e12） |
| 附录里 CCS/BECCS/捕集绝对量 | **偏低 58%，必须重画** |
