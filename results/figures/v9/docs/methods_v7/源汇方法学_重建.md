## 1. 汇的定义

### 1.1 数据源

`data/封存汇图层-Fan/` 的四张 5 km × 5 km 栅格（DSA 与 EOR 各一张储量、一张注入率），
来自中国 CO₂ 地质封存潜力与注入能力的精细网格评估：
覆盖 **24 个主要沉积盆地（17 个陆上 + 7 个海上）内的 69 个咸水层储层（陆上 53 + 海上 16）
和约 1 143–1 181 个油田**。

### 1.2 提取结果必须落进数据源自己公布的区间——已验证

`_validate_against_source_dataset` 在每次构建时自动核对并写日志：

```
storage extraction DSA: 1894.1 Gt vs published 1506-2265.0 Gt -- OK
storage extraction EOR:    8.4 Gt vs published    8.0-9.1 Gt -- OK
```

**这是最强的一条防线**：如果栅格读取、nodata 处理或单位有任何差错，
总量会立刻掉出数据源自己的 90% 区间。现在两条都在区间内，且 EOR 几乎正中
（8.37 对 8.0–9.1），说明提取是对的。

### 1.3 一个汇 = 一个连通地质封存体，不做距离合并

规则：栅格有效像元 → 2 像元（10 km）膨胀桥接同一构造内部的空隙 → 连通分量标记 →
储量 <10 Mt 的噪声分量丢弃 → **每个分量就是一个汇**，注入中心取储量加权形心。
DSA 与 EOR **分别**做，得到 33 + 70 = **103 个汇**。

**为什么去掉原来的 200 km 合并：**

1. **它没有地质依据。** 200 km 不是任何物理尺度——不是羽流半径（1 Mt/yr 注 30 年约 2–3 km），
   不是压力干扰间距，也不是盆地尺度。它只是一个让节点数变少的数值。
2. **它破坏了数据源提供的区分。** 合并按"储量多数"贴一个 `storage_type`，
   于是 70 个 EOR 地质体折进 35 个枢纽后只剩 6 个还叫 `eor`，
   **7 232 Mt 的 EOR 储量被当成 DSA 计价，丢掉 12 CNY/t 的驱油收益抵扣**。
   而中国 CCUS 文献一律把 EOR 和 DSA 分列——这是成本结构完全不同的两类汇。
3. **它拉长了输送距离。** 容量加权的"厂→最近汇"直线距离从 200 km 涨到 234 km（+17%），
   按 0.179 CNY/(t·km) 折合约 +6 CNY/t，白白抬高 CCS 成本。
4. **省下的节点数不值这个价。** 103 个汇让网络节点从 612 变成 680，MILP 规模的增量可以忽略。

**为什么 DSA 与 EOR 即使空间重叠也分开：** 因为它们价钱不一样。
`storage_cost_cny_per_t` 对 DSA 是 32，对 EOR 是 32 − 12 = 20。
不分开就只能取一个价，而"取多数"会系统性地牺牲小的那一类（EOR 储量只有 DSA 的 0.4%，永远输）。

**同时给定价加了一道保险**（`data_prep.py`）：即使有人用 `merge_distance_km` 重新打开合并，
封存成本现在也**按储量份额加权**而不是按标签取：

```python
eor_share = eor_mt / (dsa_mt + eor_mt)
storage_cost = storage_cost_cny_per_t - eor_share * eor_credit_cny_per_t
```

汇是纯的时候 `eor_share` 就是 0 或 1，与原规则完全等价；混装时也不会再有储量被"投票"投掉。

### 1.4 注入能力：为什么不能把栅格加起来

**数据源的每个像元值是"该处一口井的注入速率"**（按达西定律算的单井流量）。
所以把 67 542 个像元加起来（= 555 Gt/yr）等于假设**每 25 km² 打一口井、且井间零干扰**，
既没有工程含义，也不是数据源作者的用法——他们的县级/省级表也不是这么加的
（省级表的 Average/Min/Max 是像元分布的统计量，不是省总量）。

因此栅格总和**只作为地质上限**保留，真正起作用的是**候选场址密度**：

```
hub injectivity = (hub 像元数 / 100) × 2 Mt/yr ，单枢纽上限 200 Mt/yr
                = 每 50×50 km 一个项目 × 每个项目 2 Mt/yr
```

两个参数都有出处：

- **每个项目 2 Mt/yr**：美国 NETL 对"商业规模咸水层封存项目"的定义是
  **20–30 年注入至少 50 Mt**，即 1.7–2.5 Mt/yr。实际工程也在这个量级：
  齐鲁石化—胜利油田 1 Mt/yr（中国最大，2022 投产）、Sleipner ≈1 Mt/yr、
  Quest 1 Mt/yr、Gorgon 设计 4 Mt/yr。取 2 Mt/yr 为中值。
- **每 50×50 km 一个项目**：1 Mt/yr 注 30 年的 CO₂ 羽流半径约 2–3 km（羽流面积 12–28 km²），
  但**压力**影响范围远大于羽流，文献指出商业规模项目在没有主动压力管理时
  "需要相隔很远选址以避免彼此的压力干扰"，注入井间距按"数英里"计。
  2 500 km²/项目 是羽流面积的约 100 倍，属于保守取值。

**校验**：全国 **1 282.6 Mt/yr**，落在 ACCA21/CAEP 对 2060 年中国 CCUS 部署量
1 000–1 800 Mt/yr 的区间内。且因为像元数在合并下可加，这个总量对汇的划分方式几乎免疫
（35 个枢纽 1 282.2 → 103 个汇 1 282.6，差 0.03%）。

**海陆**：25 个海上汇（原 8 个），注入中心落在陆上省界之外的即判为海上，
其输送边按 `offshore_transport_multiplier = 1.5` 计价。
逐个检查过：没有任何一个汇同时含陆上和海上地质体，所以系数是干净作用的。

## 2. 源—汇候选管网

### 2.1 三层候选边，与 SimCCS 同构

| 层 | 内容 | 边数 | 长度口径 |
|---|---|---|---|
| 既有走廊 | 中国油气干线矢量 | 62 | **真实折线长度**（平均 2 157 个顶点/段） |
| 走廊接入支线 | 电厂/汇 → 最近走廊节点 | 241 + 69 | 直线 × 1.136 |
| Delaunay 候选 | 全部终端（350 电厂 + 103 汇）三角剖分 | 736 | 直线 × 1.136 |
| **源—汇直连** | 每个电厂 → 最近 5 个汇 | **1 569** | 直线 × 1.136，资本 ×2.8 |

前三层是原有结构，**与 SimCCS 2.0 的做法一致**：
SimCCS 用 Delaunay 三角剖分找出可行的源—汇连接，再在成本面上用 Dijkstra 求最小成本路径。
本模型没有中国的管道成本面栅格（坡度/土地利用/道路/人口），
因此用"直线 × 迂回系数"代替成本面路径——这也是华北 CCUS 研究之外的通行简化。

### 2.2 连通性是不变式，不是"尽量"

原来的 `_remove_crossing_edges` 强制候选网是**平面图**，按优先级贪心丢掉相交的低优先级边。
**平面性不是 CO₂ 管道的物理属性**，而强制它的代价是切断端点：
7 个电厂（20.4 GW）够不到任何汇，其中一个距最近汇仅 24.5 km。

SimCCS 明确把连通性当作不变式：
*"即使成本面被加权到强烈抑制穿越，也会在连接点之间找到一条路径，
因为所有的汇和源都必须至少被一条可行走廊连接。"*

重建后复制了这个语义：**先过滤，再修复**。

```python
kept = <保留不相交的边>
dropped = <被丢掉的边>
return _repair_connectivity(nodes, kept, dropped)   # 按长度从短到长放回，直到没有终端被孤立
```

本次构建日志：`removed 651 crossing candidate edges (1105 kept)` →
`restored 3 crossing edges to keep every terminal connected`。
**只放回了 3 条**——说明修复是精确的，不是把过滤撤销。

### 2.3 每个电厂到最近 5 个汇的直连弧

`OptimizationAssumptions` 里 `top_k_storage_pairs = 5` 和
`direct_fallback_capex_multiplier = 2.8` 早就声明了，
`data_prep._edge_capex_multiplier` 也早就为 `runtime_direct_fallback` 这个边类定了价——
**但仓库里从来没有任何地方产生过这个边类。** 现在 `build_direct_sink_edges` 产生它。

- **只加不减**：候选集只会变大，原来可行的解全部仍然可行，凡是优化器改变的都是它主动选择的。
- **2.8× 资本溢价**：这是走廊外自建专线的溢价，优化器只有在走廊网络确实绕远时才会用它。
- **k = 5**：与已声明的 `top_k_storage_pairs` 一致。

### 2.4 迂回系数 1.136：用中国自己的管道实测，不借文献区间

管道技经文献对"直线距离 → 实际管长"的迂回系数常用 **1.2–1.4**（并有研究指出对 48% 的路由
连 1.4 都偏低）。但本模型手上有更好的东西：**它自己的走廊图层里就有 62 段中国油气干线的真实折线几何。**

```
62 段干线：直线合计 21 418 km，实际走线合计 24 338 km
长度加权迂回系数 = 1.136        （中位 1.036，p75 1.123，p90 1.306）
按类型：天然气 1.137（n=57），原油 1.132（n=5）
```

取 **1.136**，理由有三：

1. **它是中国已建干线的实测值**，不是从国际路由借来的区间；
2. **它让同一张表内部自洽**——既有走廊边用的是真实折线长度，
   直线候选边原来用大圆距离，等于**系统性地让新建管道看起来比走廊复用便宜**，这是个建模偏差；
3. 它比文献区间保守（1.136 < 1.2），所以不会被指责"故意把新建管道做贵来抬高走廊价值"。

**既有走廊边不乘这个系数**——它们的 `length_km` 本来就是真实折线长度。

### 2.5 两道构建期断言

```python
if edges["edge_id"].duplicated().any():  raise ValueError(...)   # 下游按 edge_id 索引，重号会被静默丢弃
if _unreached_terminals(nodes, edges):   raise ValueError(...)   # 任何电厂够不到汇就直接构建失败
```

第一条不是形式主义：第一版重建时 `next_index = len(edges) + 1` 在过滤之后重发了已用编号，
`prepare_inputs` 按 `edge_id` 去重，**静默丢掉了 410 条候选边且没有任何告警**。
现在编号从最大后缀取，且构建期就会拦住。

必须与水的部分一起做，且它不是被 challenge 的主要风险点。

## 4. 仍然可以被问到的三个问题，以及回答

**Q1：为什么不用成本面最小路径（SimCCS 的完整做法）？**
因为没有中国的管道成本面栅格（坡度、土地利用、道路、人口、保护区）。
诚实的回答是：用实测迂回系数 1.136 代替，并明写这是简化。
如果要补，需要 DEM + 土地利用 + 道路网三层数据，是一个独立的数据工程。

**Q2：为什么 103 个汇里有 70 个是很小的 EOR 体？**
因为数据源本身就评估了约 1 143 个油田。EOR 全国储量只有 8.4 Gt、
可建注入能力 15.8 Mt/yr，本来就是小角色；把它们并进 DSA 只会让它们
连"小角色"都当不成（收益抵扣被投票投掉）。保留它们不增加任何求解负担。

**Q3：2.8× 的直连资本溢价是不是拍的？**
它是仓库里既有的 `direct_fallback_capex_multiplier`，与
`branch_capex_multiplier = 1.35`、`corridor_capex_multiplier = 0.4` 同一套。
这一套的相对关系（走廊复用最便宜、走廊接入次之、专线最贵）是合理的，
绝对值是本模型自己的假设，已经在敏感性里（`SA_pipe_mid` / `SA_pipe_full`）扫过。
**如果要更 solid，应该把 2.8 也纳入敏感性扫描**——这是下一轮该补的。

## 4b. 2026-09-03 追加：海上封存体按盆地合并（v9 重做所用输入）

§1.3 的"一个汇 = 一个连通封存体"在陆上给出 78 个汇，与文献（Wei et al. 2023 的 113 个）
是同一个量级；但海上给出 25 个，而数据源自己只划了 **7 个海上盆地**，文献里也是
盆地级的 5–8 个。差的不是封存体的数量，是海上栅格被海底地形切碎了：同一个盆地在
5 km 栅格上是好几块互不相连的斑，陆上没有这个问题。

**合并规则（数据导出，不是拍距离）：** 把 DSA 栅格做形态学膨胀后取连通域当"盆地"，
海上封存体落在同一盆地、且封存类型相同的合并成一个汇。膨胀半径扫描：

| 膨胀 | 海上盆地数 | 判断 |
|---|---|---|
| 10 km（2 px） | 9 | 仍碎 |
| 20 km（4 px） | 8 | 仍碎 |
| **30 km（6 px）** | **7** | **= 数据源的 7 个海上盆地** |
| 40 km（8 px） | 5 | 过头：珠江口与北部湾、渤海与北黄海被错误粘连 |

取 30 km。DSA 与 EOR **仍分列**（§1.3 的定价理由不变），因此海上汇 = 7 个 DSA + 4 个 EOR
= 11 个；全国 89 个汇。合并只改变汇的个数，不改变可建注入能力：海上 476.0 Mt/yr、
陆上 874.4 Mt/yr，合并前后完全一致（单体上限 200 Mt/yr 在合并后仍逐汇施加）。
陆上一个都不动。

实现：`builders/storage.py` 的 `_offshore_basin_labels` / `_merge_offshore_by_basin`，
入口 `scripts/build_storage_inputs.py --offshore-basin-dilation-px 6`。默认仍为不合并，
v8 树（103 汇）可原样复现。候选管网随之从 2 677 条边变为 2 651 条、节点 680 → 666。
这是新的输入版本（作者决定沿用 v9 目录，旧图冻结到 `v9/frozen_103sink_lost_tree/`），
与 v8 及 v9 旧图的结果不得相减。
